# 要件定義

## 0. 方針転換の経緯(2026-08時点)

当初は「記録者本人1人が秘密URLで入力し、誰でも公開ページで閲覧できる」個人用ツールとして構築した。運用を経て、将来的には無料で一般公開し、複数のユーザーがそれぞれ自分の記録を管理できる製品として育てたいという方針に転換した。これに伴い、以下を転換する。

- 秘密URL方式の書き込み保護 → 通常のログイン認証(Google / メールアドレス・パスワード)に置き換える
- 「誰でも閲覧できる公開サイト」→ 廃止し、ログイン後の本人専用ダッシュボードに一本化する(US-3・US-4を更新)
- 1人固定のサイクル定義(Push/Pull/Legs/Rest) → ユーザーごとに自由に設定できる形にする
- 対応する設計変更は [design.md](design.md) を参照

## 1. 背景・目的
筋トレの記録入力・進捗確認を行うWebサイトを、無料構成で構築する。当初は自分専用ツールとして始めたが(元々は `筋トレ管理表.md` での手動管理からの脱却が目的)、将来的には無料で一般公開し、複数のユーザーがそれぞれ自分の記録を管理できる製品として育てる方針(§0)。

## 2. 利用者
| 利用者 | できること |
| :--- | :--- |
| ユーザー(ログイン要) | アカウントを作成してログインし、自分専用のダッシュボードで記録の入力・管理表の編集・プロフィール管理を行う。他のユーザーのデータは一切参照・変更できない |

## 3. ユーザーストーリーと受け入れ基準

### US-1: ユーザーとして、トレーニング後にその場でセットごとの記録を入力したい
- **受け入れ基準**
  - 日付・種目を選び、セットごとに重量と回数を入力して送信できる
  - 送信内容は記録ログとして保存され、あとから参照できる
  - スマートフォンから問題なく入力できる(レスポンシブ対応)

### US-2: ユーザーとして、管理表の「現在値」を手入力せずに済ませたい
- **受け入れ基準**
  - 記録ログを送信すると、該当種目の管理表「現在値」が自動更新される
  - 算出ロジックは [design.md](design.md) の定義に従う

### US-3: ユーザーとして、ログイン後に自分の管理表(目標・現在値)を見たい
- **受け入れ基準**
  - ログインすると、自分のダッシュボードで管理表が見られる
  - 自分のサイクル・分類ごとに整理されて表示される
  - 他のユーザーの管理表は一切見えない

### US-4: ユーザーとして、種目ごとの進捗をグラフで見たい
- **受け入れ基準**
  - 種目を選ぶと、重量推移(折れ線)と総作業量推移(折れ線)が見られる
  - データがまだない種目は「記録なし」等の表示になる

## 4. スコープ外(決定事項)
- 課金・有料プラン(無料公開のみ)
- カロリー計算・栄養管理機能(性別・生年月日はプロフィールとして持つが、計算機能自体は今回スコープ外。将来の拡張候補)
- プッシュ通知・メール通知(パスワードリセット等の認証系メールを除く)
- アカウント削除の猶予期間・データ復元機能(US-15の通り即時削除のみ)
- CSVインポート機能(エクスポート(US-17)のみ提供。他アプリ・スプレッドシートからの移行需要が実際に出てきたら追加を検討する)

## 5. 決定事項(追加)

### US-5: ユーザーとして、入力ミスをした記録を修正・削除したい
- **受け入れ基準**
  - ダッシュボードで直近の記録一覧を確認できる
  - 一覧から特定の記録(1セット分)を選んで、重量・回数を修正できる
  - 一覧から特定の記録を削除できる
  - 修正・削除すると、該当種目の管理表「現在値」が自動で再計算される([design.md](design.md) §2.9)

### US-6: サイクルの自動判定は行わない
- 「今日はどのサイクルか」をサイト側で判定・表示する機能は持たない。
- 管理表は常に自分の全サイクルを並列表示し、ユーザーが自分で選んで見る。

### US-7: ユーザーとして、目標値の更新・種目の追加/削除をサイトから行いたい
- **受け入れ基準**
  - ダッシュボードから、既存種目の目標重量・目標回数・目標セットを編集して保存できる
  - ダッシュボードから、サイクル・分類・種目名・目標値を指定して新しい種目を追加できる
  - ダッシュボードから、不要になった種目を削除できる
  - これにより、運用開始後にスプレッドシートを直接編集する必要はなくなる(初期データ移行(US-8)を除く)

### US-8: 開発者本人の既存データを、最初のユーザーアカウントとして引き継ぐ(達成済み)
- 運用開始時、既存の `筋トレ管理表.md` に記載された現在値をそのまま、開発者自身の最初のアカウントのデータとして転記してスタートする。
- 記録ログが空でも、管理表の「現在値」が空欄にならないようにする。
- `筋トレ管理表.md` 自体は新システム稼働後も削除せず、控え・バックアップとして並行して残す。
- この初期移行(1回限りの作業)は、記録者がフォームやDBに直接値を投入して行う。件数が少なく(14種目程度)、サイトのフォームを繰り返し操作するより早いため。運用開始後の追加・編集・削除はUS-7の通りサイトから行う。
- 補足(2026-08、§0.1のマルチユーザー化に伴う2回目の移行): このUS-8は最初のGoogle Sheets→XServer移行時のもので、既に完了している。今回のマルチユーザー化では、その結果として既にXServer上のDBに溜まっている実際の記録履歴(`logs`)を手入力し直すのは非現実的なため、SQLスクリプトによる自動移行を行う([design.md](design.md) §5、`sql/migrate_to_multiuser.sql`)。

### US-9: (撤回)公開サイトは検索エンジンにインデックスさせない
- 旧要件。無料公開して新規ユーザーに見つけてもらいたいという方針(§0)のため撤回する。
- ログイン前のトップページ(サインアップ導線)はむしろ検索エンジンに見つけてもらいたいため、noindexは設定しない。
- ログイン後のダッシュボードはそもそも認証必須でアクセスできないため、検索エンジンに内容が渡ることはない(結果的にクロール対象外になる)。

## 6. マルチユーザー化に伴う追加要件(2026-08、§0対応)

### US-10: 未登録の訪問者として、Googleアカウントまたはメールアドレス+パスワードでアカウントを作成し、ログインしたい
- **受け入れ基準**
  - トップページからサインアップ・ログインができる
  - Googleアカウントでのサインアップ・ログインができる
  - メールアドレス+パスワードでのサインアップ・ログインができ、パスワードを忘れた場合はメールでリセットできる
  - ログインしていない状態では、他人のダッシュボードや記録データには一切アクセスできない
  - メール/パスワードで登録済みのメールアドレスと同じGoogleアカウントでログインした場合、別アカウントにはならず既存アカウントに統合される([design.md](design.md) §2.1)

### US-11: ユーザーとして、自分の記録が他のユーザーから見えないことを期待する
- **受け入れ基準**
  - あるユーザーのサイクル・種目・記録・体重データは、そのユーザー自身のログインセッションでのみ取得・変更できる
  - APIは常にログイン中のユーザーでデータを絞り込み、リクエストパラメータでのユーザー指定は一切信用しない

### US-12: 新規ユーザーとして、初めてログインしたときにサイクル構成を簡単に用意したい
- **受け入れ基準**
  - 初回ログイン時、いくつかのサイクル構成テンプレート(例: 「Push/Pull/Legs/Restの4分割」「Upper/Lowerの2分割」等)から選んで自分のサイクルとして登録できる
  - テンプレートを使わず、自分でゼロからサイクルを作ることもできる
  - テンプレートにはサイクルの構成のみが含まれ、種目は含まれない(登録後にUS-7の操作で追加する)

### US-13: ユーザーとして、オンボーディング後もサイクル構成を追加・変更・削除したい
- **受け入れ基準**
  - 設定画面からサイクルを追加できる
  - サイクル名を変更できる
  - 種目が1件も紐づいていないサイクルは削除できる(種目が紐づく場合は削除不可)

### US-14: ユーザーとして、自分のプロフィール(生年月日・性別)を設定したい
- **受け入れ基準**
  - 設定画面で生年月日・性別(男性/女性/回答しない)を入力・変更できる
  - 未入力のままでも他の機能は問題なく使える(任意項目)

### US-15: ユーザーとして、体重の推移を記録してグラフで見たい
- **受け入れ基準**
  - 日付・体重を入力して記録できる
  - 種目の進捗グラフと同様に、期間を切り替えて体重推移の折れ線グラフを見られる

### US-16: ユーザーとして、アカウントを削除すると自分のデータが即座に消えることを期待する
- **受け入れ基準**
  - 設定画面から退会操作ができ、確認後に即座にアカウント・関連する全データ(サイクル・種目・記録・体重記録)が削除される
  - 猶予期間は設けない(削除は取り消せないことを確認ダイアログで明示する)

### US-17: ユーザーとして、自分の記録をCSVでダウンロードしたい
- **受け入れ基準**
  - 設定画面等から、トレーニング記録をCSV形式でダウンロードできる
  - 体重記録もあわせてダウンロードできる
