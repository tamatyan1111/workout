# 要件定義

## 1. 背景・目的
筋トレの記録入力・進捗確認・管理表の公開を行うWebサイトを、無料構成で構築する。
現在は `筋トレ管理表.md` で手動管理しているが、記録の蓄積・進捗の可視化ができないため。

## 2. 利用者
| 利用者 | できること |
| :--- | :--- |
| 自分(記録者) | 秘密URLから記録の入力・管理表更新を行う |
| 誰でも(閲覧者) | 公開サイトで管理表・進捗グラフを閲覧する(入力不可) |

## 3. ユーザーストーリーと受け入れ基準

### US-1: 記録者として、トレーニング後にその場でセットごとの記録を入力したい
- **受け入れ基準**
  - 日付・種目を選び、セットごとに重量と回数を入力して送信できる
  - 送信内容は記録ログとして保存され、あとから参照できる
  - スマートフォンから問題なく入力できる(レスポンシブ対応)

### US-2: 記録者として、管理表の「現在値」を手入力せずに済ませたい
- **受け入れ基準**
  - 記録ログを送信すると、該当種目の管理表「現在値」が自動更新される
  - 算出ロジックは [design.md](design.md) の定義に従う

### US-3: 誰でも、現在の管理表(目標・現在値)を見たい
- **受け入れ基準**
  - 公開サイトにアクセスするだけで、ログイン不要で管理表が見られる
  - サイクル・分類ごとに整理されて表示される

### US-4: 誰でも、種目ごとの進捗をグラフで見たい
- **受け入れ基準**
  - 種目を選ぶと、重量推移(折れ線)と総作業量推移(折れ線)が見られる
  - データがまだない種目は「記録なし」等の表示になる

## 4. スコープ外(決定事項)
- 記録者以外による書き込み・認証機能

## 5. 決定事項(追加)

### US-5: 記録者として、入力ミスをした記録を修正・削除したい
- **受け入れ基準**
  - 入力ページで直近の記録一覧を確認できる
  - 一覧から特定の記録(1セット分)を選んで、重量・回数を修正できる
  - 一覧から特定の記録を削除できる
  - 修正・削除すると、該当種目の管理表「現在値」が自動で再計算される([design.md](design.md) §2.4)

### US-6: サイクルの自動判定は行わない
- 「今日はどのサイクルか」をサイト側で判定・表示する機能は持たない。
- 管理表は常に全サイクル(1〜4)を並列表示し、記録者が自分で選んで見る。

### US-7: 記録者として、目標値の更新・種目の追加/削除をサイトから行いたい
- **受け入れ基準**
  - 入力ページから、既存種目の目標重量・目標回数・目標セットを編集して保存できる
  - 入力ページから、サイクル・分類・種目名・目標値を指定して新しい種目を追加できる
  - 入力ページから、不要になった種目を削除できる
  - これにより、運用開始後にスプレッドシートを直接編集する必要はなくなる(初期データ移行(US-8)を除く)

### US-8: 既存の管理表の値を初期データとして引き継ぐ
- 運用開始時、既存の `筋トレ管理表.md` に記載された現在値をそのまま管理表シートに転記してスタートする。
- 記録ログが空でも、管理表の「現在値」が空欄にならないようにする。
- `筋トレ管理表.md` 自体は新システム稼働後も削除せず、控え・バックアップとして並行して残す。
- この初期移行(1回限りの作業)は、記録者がスプレッドシートに直接値を転記して行う。件数が少なく(14種目程度)、サイトのフォームを繰り返し操作するより早いため。運用開始後の追加・編集・削除はUS-7の通りサイトから行う。

### US-9: 公開サイトは検索エンジンにインデックスさせない
- URLを知っている人だけが閲覧できればよく、Google等の検索結果には出したくない。
- noindexメタタグ等でクロールを拒否する。

## 6. 未決定
現時点で要件面の未決定事項はなし。設計上の未確定事項(実装フェーズ直前に決定)は [design.md](design.md) §5 を参照。
